# 운영 반영 전 확인

## 기능과 배포 순서

개발 브랜치에서 변경사항을 검증하고, 승인 후 DB 마이그레이션과 웹 배포를 각각 진행합니다. 신규 마이그레이션 001~005는 기존 거북이 서비스 스키마 위에 번호 순서대로 한 번씩 적용합니다. 이전 게임 리뷰 스키마와 tests/supabase의 합성 데이터베이스는 운영 초기화에 사용하지 않습니다.

NEXT_PUBLIC_MEMBER_SAFETY=true로 빌드하면 신고·차단과 탈퇴 신청 UI가 활성화됩니다. 자동 탈퇴 처리는 서버 전용 WITHDRAWAL_PROCESSING_ENABLED와 서버 키를 별도로 설정해야 합니다. 처리 중인 요청 재개 및 사진 소유권 확인 절차는 [회원 탈퇴 운영 문서](./withdrawal.md)를 참조하세요.

## 검증 범위

개발 브랜치의 GitHub Actions는 임시 Supabase에서 Auth·Storage·PostgREST를 실행합니다. A의 탈퇴 후 B의 답글·사진 보존, A의 개인 기록 정리, 실패 후 재시도, 중복 요청, 사진 쓰기 차단을 검사합니다. 신고 대상 중복과 시간당 10건 제한, 신고자 정보 접근 제한, 차단 관계 격리도 검사합니다. 실행 중에는 운영 프로젝트 URL이나 키를 설정하지 않습니다.

공개 게시글은 비회원에게 보이는 제목과 기존 공유 이미지를 사용합니다. 익명화·삭제된 게시글에는 검색 제외 지시를 제공합니다. 검색엔진과 메신저가 이전에 저장한 미리보기는 각 서비스의 갱신 시점에 따라 달라질 수 있습니다.

## 반영 전 확인 및 복구

실제 서비스와 일치하는 테스트용 스키마에서 기존 RPC, 정책, 트리거, 이미지 소유 경로와 새 마이그레이션을 함께 확인합니다. 테스트용 실제 기기로 이메일 인증·복구와 사진 첨부를 확인하고, 신고 사유·차단·탈퇴 요청 정보의 보관 기간과 문의 처리 방침을 확정합니다.

문제 발생 시 신규 탈퇴 처리를 끄고 운영자 재시도를 중지합니다. 웹은 이전 Vercel 배포로 복원하거나 기능 플래그를 끄고 다시 빌드합니다. 접수된 신고 및 탈퇴 요청 기록은 보존합니다. 완료된 탈퇴나 삭제된 사진은 웹 배포 롤백으로 복구되지 않습니다.

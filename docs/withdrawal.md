# 회원 탈퇴 처리

개발 환경에서 먼저 001~005 마이그레이션을 순서대로 적용하고 테스트 계정 두 개로 본인 재인증, 다른 회원 답글 보존, 사진 업로드·정리와 인증 계정 삭제를 확인합니다. 004는 Supabase 관리 스키마에 트리거를 만들고, 005는 신고 빈도 제한을 추가하므로 대상 환경에서 마이그레이션 권한과 Auth·Storage 호환성을 확인해야 합니다.

NEXT_PUBLIC_MEMBER_SAFETY=true로 빌드하면 본인 확인과 요청 접수 화면이 활성화됩니다. 자동 처리는 서버 전용 WITHDRAWAL_PROCESSING_ENABLED=true 및 SUPABASE_SERVICE_ROLE_KEY가 별도로 필요합니다. 비밀키를 NEXT_PUBLIC 변수로 설정하지 마세요. 자동 처리 비활성 시 요청은 운영자 확인 대기로 남습니다.

인증 API는 토큰의 사용자 ID만 사용합니다. DB에 재인증된 탈퇴 요청이 존재해야 정리가 시작됩니다. 먼저 `lt_prepare_withdrawal`에서 개인정보와 작성 내용을 익명화하고 성장 기록·개체·좋아요를 정리해 이 단계를 커밋합니다. 그다음 Storage 사진을 지우고 Auth 계정을 삭제합니다. 계정 삭제 시점에 오류가 발생하면 DB 본문 변경은 롤백되고 요청이 남습니다. 선처리 단계가 저장된 뒤 사진 정리나 Auth 삭제에 실패해도 본문은 이미 익명화되어 원문이 사진 없는 상태로 다시 노출되지 않습니다. 계정은 남은 작업을 재시도할 때까지 로그인 상태로 남을 수 있고 사진 일부는 삭제된 상태일 수 있습니다. 사진 원본은 현재 백업하지 않으므로 Storage 삭제 후 복구할 수 없습니다. 소유자가 없는 이전 사진이나 경로가 일치하지 않는 사진은 운영자가 소유권을 확인해야 합니다.

서버 요청 1회에서 최대 3묶음(묶음당 최대 100개)을 처리합니다. 초과하거나 네트워크·권한 문제가 생긴 요청은 서버에서 SUPABASE_URL과 SUPABASE_SERVICE_ROLE_KEY를 설정하고 다음 명령으로 재처리합니다.

```
node scripts/process-withdrawal.mjs <신청자-UUID> <프로젝트-ref> --process-verified-request
```

중단 시 서버 처리 플래그를 끄고 운영자 작업도 중지합니다. 접수·처리 중인 요청을 보존하며, 처리 시작 후 해당 회원의 신규 사진 쓰기는 제한됩니다. 이미 완료된 탈퇴는 웹 배포 롤백으로 복구할 수 없습니다.
